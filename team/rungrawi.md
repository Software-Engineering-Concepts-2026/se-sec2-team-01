## (•̀ᴗ•́)و ทำไมอยากเรียน SE (Software Engineering)

> การเขียนโค้ดให้รันผ่านเป็นเพียงจุดเริ่มต้น แต่การทำให้ระบบคงอยู่และเติบโตได้อย่างยั่งยืนคือหัวใจสำคัญ

* **Systematic Engineering:** ต้องการเข้าใจกระบวนการพัฒนาซอฟต์แวร์ทั้ง Lifecycle อย่างมีแบบแผน ตั้งแต่ Architecture Design ไปจนถึง Maintenance
* **Maintainability & Scalability:** เพื่อฝึกฝนทักษะการออกแบบ Codebase ขนาดใหญ่ที่ Clean, Testable และสามารถทำงานร่วมกับทีมได้อย่างมีมาตรฐานระดับ Professional

## (ノ°Д°)ノ Broken Window ที่เคยเจอ (The Broken Window Theory)

> ทฤษฎีหน้าต่างแตก (Broken Window Theory): เมื่อมีจุดบกพร่องเล็ก ๆ ถูกปล่อยทิ้งไว้โดยไม่แก้ไข จะส่งผลให้เกิดความละเลยตามมาเรื่อย ๆ จนระบบพังทลายในที่สุด (´-ω-`)

### [1] Window คืออะไร?
* ในโปรเจกต์ที่ผ่านมา มีการละเลยไม่จัดระเบียบโครงสร้างโฟลเดอร์ และตั้งชื่อตัวแปรแบบลวก ๆ รวมถึงใช้ Type แบบหลวม ๆ (`any`) เพียงเพราะต้องการรีบส่งงานให้ทันเวลา

### [2] ผลกระทบที่เกิดขึ้น
* เมื่อเพื่อนร่วมทีมนำโค้ดไปพัฒนาต่อ เกิดความสับสนใน Data Flow จนนำไปสู่การเขียนโค้ดแทรกแบบทางลัด (Bad code / Workarounds) ทับถมกันไปเรื่อย ๆ ทำให้เกิด **Technical Debt** มหาศาล และเกิด Bug ซ้ำซ้อนที่เสียเวลา Debug ยาวนาน

### [3] ถ้าแก้ทันทีจะป้องกันอะไร?
* หากตั้ง Code Standard และรีบ Refactor จุดที่เริ่มเละทันทีตั้งแต่ Commit แรก จะช่วยป้องกันไม่ให้ทีมเริ่มเขียนโค้ดแบบทางลัดตาม ลดหนี้ทางเทคนิค และทำให้โปรเจกต์สามารถ Maintain ต่อยอดได้อย่างราบรื่น ٩(ˊᗜˋ*)و

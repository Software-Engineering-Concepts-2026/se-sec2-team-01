# Reflection - Adisak Kaosang

## 1. Software Entropy และ Broken Window Theory

จากโปรเจกต์ที่เคยทำ ผมเคยปล่อยให้โค้ดบางส่วนไม่มีการจัดระเบียบและไม่ได้ลบโค้ดที่ไม่ได้ใช้งาน ทำให้เมื่อเวลาผ่านไป การแก้ไขและเพิ่มฟีเจอร์ใหม่ทำได้ยากขึ้น และเกิดข้อผิดพลาดได้ง่าย เพราะโค้ดอ่านยากและดูแลรักษายาก

## 2. Take Responsibility และ Provide Options, Don't Make Lame Excuses

ผมเข้าใจว่า Take Responsibility คือการรับผิดชอบต่อหน้าที่ของตนเอง เมื่อเกิดปัญหาไม่ควรหาข้ออ้าง แต่ควรแจ้งทีมพร้อมเสนอแนวทางแก้ไข เช่น หากทำงานไม่เสร็จตามกำหนด ผมจะแจ้งให้ทีมทราบล่วงหน้า พร้อมเสนอว่าจะขอเวลาเพิ่มหรือแบ่งงานบางส่วนให้เพื่อนช่วย เพื่อให้โปรเจกต์ดำเนินต่อไปได้
